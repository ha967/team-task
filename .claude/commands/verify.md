对这个项目的当前改动执行验收。spec：$ARGUMENTS（若为空，则从 `docs/specs/` 里找与本轮改动对应的文件；找不到就跳过 AC 核对并提示我）。

## L0 机器门禁（先跑，不通过就别往下走）

```bash
bash .claude/hooks/gate.sh < /dev/null
```

非 0 退出 → 把报错原文贴出来并停下，不要顺手去改。

## L1 独立差分审查

1. 收集完整改动，**包括未跟踪的新文件**：

```bash
git status --short && git diff && git diff --staged
```

未跟踪文件用 `Read` 逐个读，它们不会出现在 `git diff` 里。

2. 用 Agent 工具起 **`reviewer`** 子代理，把「spec 内容 + 完整 diff + 新增文件内容」交给它。

   **关键：不要把你的判断传给它。** 不许写「我担心权限那块」「应该没问题了」这类话 —— 一旦给了结论，它只会去找证据支持你。只给事实。

3. 拿到它的 `阻塞项` / `建议项`，原样呈现给我。

## L2 人工逐条核对验收标准

从 spec 里取出 AC，逐条给出判定和证据：

| # | 验收标准 | 判定 | 证据 |
| --- | --- | --- | --- |
| 1 | <AC 原文> | ✅ 通过 / ❌ 不通过 / ⚠️ 需人工确认 | `path:line` / 测试输出 / 命令结果 |

规矩：

- **不许凭「代码看起来做了」判通过**，要么有测试/命令输出，要么标 ⚠️ 让我自己验。
- 人工判定类的 AC 一律标 ⚠️，不要替我做判断。
- 你**做对了但和我想要的不一样**这种情况，只有这一层能发现 —— 所以这层不许省。

## 输出

```
## 门禁
<通过 / 失败原文>

## 审查结论
<阻塞项数量；若无则写「无阻塞项」>

## AC 核对
<上面的表格>

## 待我决定
<需要我拍板的点：审查建议项是否要修、AC 未通过项怎么处理>
```

**不要自动修问题。** 列出修复项，等我点头。唯一的例外：门禁报错属于格式 / 导入后缀这类纯机械问题，可以直接修。

## 收尾（沉淀）

最后问我一句：这轮审查里有没有哪条是新问题 —— 如果有，把它加进 `.claude/agents/reviewer.md` 的清单。这套清单靠每次验收攒出来的条目才会变准。
